## 1. Что такое Алиса

**Alice** (исходник: `github.com/root3315/Alice_Chat-Bot-Genius`) — автономный «живой»
Telegram-компаньон на TypeScript/Node. Это **не** бот-автоответчик: у неё свой
цикл «жизни» (тик), она наблюдает за чатами, думает про себя, сама решает, когда
и кому написать, реагирует на настроение и паузы.

**Что мы с ней сделали:**
- Перевели «мозг» на **Claude** через **Max-подписку** (легально, без API-ключа).
- **Русифицировали** (персона, весь model-facing текст, её записи в БД).
- Дали **живой голос** (клон выбранного голоса, XTTS-v2) и **слух** (Whisper).
- Настроили **доступ**: личка — только тебе, группы — открыты.
- Часовой пояс — **Ташкент (UTC+5)**.

Технически она работает на аккаунте-юзерботе (MTProto, библиотека **mtcute**),
не на Bot API. Аккаунт: телефон `+19403703845`, юзернейм **@MrPumpkin1_bot**
(суффикс `_bot` — просто часть ника, это пользовательский аккаунт, не бот).

## 2. Архитектура «изнутри»

**Главный цикл — EVOLVE + ACT (тик):**
- **EVOLVE** — на каждом тике пересчитывает «давления», выбирает цель (какой чат)
  и «голос» (тон действия), ставит действие в очередь.
- **ACT / react-orchestrator** — исполняет: создаёт engagement-слот, смотрит чат,
  решает написать/смолчать. Между чатами есть «switch cost» (1.5с) — как у
  человека переключение внимания.
- Результат тика: `outcome` = `message_sent` / `silence` / `observe_success` и т.п.
  «silence» = подумала, но решила промолчать (это нормально).

**Давления P1–P6** — внутренние «силы», которые толкают её к действию (скучно,
кто-то ждёт ответа, давно не писала, и т.п.). В простое часть давлений = 0
(`WARN [pressure_dead] P4 = 0.00` — **это норма**, просто нет входящих).

**Voices (голоса личности)** — curiosity / sociability / diligence и др. Это «с
каким настроем» она делает действие, а не разные модели.

**Граф мира (WorldModel)** — узлы `channel:telegram:<id>` и `contact:telegram:<id>`,
связи между ними, динамические свойства (mentions_alice, reachability и т.д.).
Одного человека в разных чатах она сводит к одному контакту.

**Dunbar-ярусы [5, 15, 50, 150, 500]** — круги близости. **5 = самые близкие**,
**500 = самые далёкие/едва знакомые** (НЕ наоборот).

**Векторы отношений** к каждому контакту: familiarity (знакомость), trust
(доверие), affection (привязанность), attraction (симпатия), respect (уважение).

**Моды (модули поведения):** soul, pressure, memory, threads, social_case,
relationships, observer, consolidation, learning, consciousness, strategy,
scheduler, feeds, channel, diary, episode. Их состояния сохраняются в БД и
восстанавливаются при старте.

**Скиллы** (shell-команды, которые она «исполняет») гоняются в **Docker-песочнице**
(на Windows — runtime `runc`, т.к. gVisor `runsc` недоступен), с урезанными правами.

**БД** — SQLite (`runtime/alice.db`), с FTS (полнотекстовый поиск) по сообщениям.

## 4. Мозг — Claude через Max-подписку

**Файл:** `_study/claude-proxy/claude_proxy.py` (порт **8787**).
Это маленький Python-сервис: наружу даёт OpenAI-формат (`/v1/chat/completions`),
а внутри гоняет **официальный `claude` CLI** через **OAuth Max-подписки**.

**Почему легально (без бана):**
- Тот же `claude` CLI, что в твоём терминале. Авторизация — OAuth подписки.
- `ANTHROPIC_API_KEY` намеренно НЕ задан (прокси даже вычищает его у дочернего
  процесса) — иначе ушло бы на платный API.
- Мы НЕ дёргаем `api.anthropic.com` напрямую и НЕ подменяем токен. Именно эти
  хаки и приводят к банам — мы их не делаем. Расходуется лимит подписки.

**Роутинг моделей** (в `config.toml`):
- Мозг (`first_pass`, `tool_tick`) → **Sonnet** (богаче, живее).
- Eval / auxiliary / reflect → **Haiku** (дешевле/быстрее, офлайн).

**Хитрости:**
- `CLEAN_CWD` — CLI запускается в чистой временной папке, чтобы не грузить
  контекст Astracore (~21k токенов) → тик мозга ускорился до ~5–6с.
- Vision — нативный multimodal: картинка идёт как base64-блок через
  `--input-format stream-json` (Claude видит её за один проход, ~5с).
- Тёплый пул процессов сознательно НЕ делаем (Alice stateless, claude -p копил бы
  контекст → утечка/смешивание).

**Важно:** веб-поиск через подписку **не работает** (`claude -p` на OAuth даёт
`web_search_requests=0`, модель галлюцинирует «результаты»). Серверный веб-поиск —
платная API-фича. Альтернатива на будущее — keyless DuckDuckGo в прокси.

## 5. Голос (TTS) — XTTS-v2 клон

**Файл:** `_study/claude-proxy/tts_proxy.py` (порт **5123**, MiniMax-совместимый
`/v1/t2a_v2`). Движок по умолчанию — **xtts**, при сбое фолбэк edge-tts → gTTS.

- **Модель:** XTTS-v2 (Coqui) на GPU (RTX 3070). Бесплатно, без ключа.
- **Голос:** клон из `voice-ref/_reference.wav` — склеен скриптом `make_reference.py`
  из 33 коротких mp3 одного женского голоса (~90с чистой речи).
- **Скорость:** `XTTS_SPEED=0.95` (чуть медленнее дефолта — комфортнее).
- **Кросс-язычно:** образец мог быть на любом языке, Алиса говорит по-русски его
  тембром.
- Шим отдаёт **WAV**, а ffmpeg у самой Алисы перекодирует в OGG/Opus для
  голосового сообщения Telegram.
- **VRAM-оптимизация:** XTTS жрал 7.6 ГБ (раздутый кэш PyTorch) → после
  `torch.cuda.empty_cache()` + `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`
  занимает ~2 ГБ, чтобы влез рядом с Whisper на 8-гиговой карте.

**Витрина голосов** (если захочешь сменить): `xtts_voices.py` (встроенные ~58
голосов), `silero_voices.py` (Silero v5), образцы складываются в `voice-samples\`.
Сменить голос — правкой `.env-tts` (`XTTS_SPEAKER` или `XTTS_SPEAKER_WAV`).

> История выбора: стоковые голоса (XTTS-встроенные, Silero, edge-мультиязычные)
> тебе не зашли («роботизированно / так себе»), поэтому пошли в **клонирование**
> присланного голоса — это и дало нужный результат.

## 6. Слух (ASR) — Whisper

**Файл:** `_study/claude-proxy/asr_proxy.py` (порт **5124**, OpenAI-совместимый
`/v1/audio/transcriptions`). Движок — **faster-whisper**, модель **large-v3**.

- На **GPU (CUDA, int8_float16)** — распознавание ~**3с** на 31-секундный клип
  (на CPU было бы ~32с). Точность отличная для русского.
- OGG/Opus от Telegram декодируется внутри faster-whisper (PyAV) — системный
  ffmpeg не нужен.
- **DLL-фикс под Windows:** ctranslate2 не находил cudnn/cublas → добавляем
  `torch/lib` в путь поиска DLL (`os.add_dll_directory`), используя те, что привёз
  torch (cu121).
- Подключение к Алисе: `config.toml [asr] base_url = http://127.0.0.1:5124/v1`,
  в `.env` — `ASR_API_KEY=dummy` (иначе слух выключен), таймаут ASR поднят до 60с.

**Проверено в бою:** в логе видно `Voice transcribed` (распознала твоё голосовое)
и `POST /telegram/voice → 200` (ответила своим голосом-клоном).

## 7. Зрение и стикеры

- **Vision ВКЛЮЧЁН** — нативный multimodal Claude через прокси (см. §4). Описывает
  фото и стикеры за ~5с. Для анимированных стикеров/видео берёт один кадр
  (превью); видео целиком не обрабатывает.
- Аниме-фильтр стикеров **ослаблен** — описываются все стикеры.
- Иногда `Vision API call failed (timeout)` на стикере или `OCR timeout` на
  скринах — **некритично** (фолбэк, фото при этом описываются нормально).
- Если стикер не подобрался по ключевому слову — есть фолбэк `pickAnySticker`
  (берёт любой, чтобы не падать). Для эмоциональных стикеров стоит добавить
  character-стикерпак в её аккаунт.

## 8. Личность и поведение

**Персона** — `runtime/SOUL.md` (полностью на русском). Алиса — молодая девушка:
мягкая, иногда резкая на язык, думает больше, чем говорит; чаще наблюдает, но если
тема цепляет — вспыхивает. Говорит как живой человек в переписке, без казённого
тона ассистента, без emoji-спама.

**Самоузнавание (как зовут):**
- В `SOUL.md` прописано: её ник **@MrPumpkin1_bot**, и что «Алиса» / «Alice» /
  ник — это обращение к ней.
- Детекция упоминаний (`mapper.ts`) ловит имя и латиницей, и кириллицей (склонения
  + звательное «Алис»), без ложных срабатываний на «реалист/специалист».

**Приоритет ответа:**
- **Личка:** отвечает на **всё** сразу (каждое сообщение = directed).
- **Группа:** быстро отвечает на `@`-ник и reply (явное обращение). На имя
  «Алиса, …» — **замечает**, но отвечает **по настроению** (сознательно НЕ форсим
  — чтобы сохранить сдержанный характер). В 3-м лице («вчера Алиса…») не лезет.

**Спокойный/тихий период** — норма: «silence»-исходы, мысли про тишину, P4/P5 = 0.
Она не гоняется за вниманием.

## 9. Доступ и приватность

- **Личка — только твой аккаунт** (`TELEGRAM_ADMIN = 5707638365`, @Pumpkin2008).
  Чужие ЛС и её собственное «Избранное»/Saved Messages **игнорируются** (в коде
  `events.ts`). Это сделано потому, что в Saved Messages лежала запрещёнка/ссылки.
- **Группы — открыты** (`config.toml [focus] whitelist = []`): может работать в
  любой группе/канале.
- **`membership-guard`** — анти-бан: не даёт писать в группы, где её **нет** (где
  её кикнули/она не вступила). Вступать не мешает.
- Вступление в группу: у неё есть механизм (в логе виден `POST /telegram/join`).
  Если при добавлении статус висит «приглашена» — причина обычно в том, что её
  надо ВСТУПИТЬ активно (по invite-ссылке), а не пассивно добавить. Приватность
  «кто может добавлять» у её аккаунта = «Все», лимитов нет (@SpamBot чист).

## 11. Что умеет / чего не умеет

**✅ Умеет:**
- Переписку (текст), автономную инициативу, наблюдение, дневник, рефлексию.
- **Голосовые сообщения**: слышит твои (Whisper) и отвечает своим голосом (XTTS-клон).
- **Зрение**: описывает фото и стикеры (нативный Claude).
- Реакции (❤ и т.п.), стикеры, скиллы в Docker-песочнице.
- Вступать в группы (по ссылке), работать в любых группах.

**❌ Пока НЕ умеет / отложено:**
- **Живые звонки** (войс-чаты, реал-тайм созвон) — **отложено**. Реализуемо только
  через pytgcalls/ntgcalls + вторая сессия + мост к мозгу; главный блокер —
  латентность (whisper→Claude ~3-6с→XTTS = ~6-10с на реплику → вышел бы медленный
  пошаговый ассистент, не живой разговор). Вернуться, если появится быстрый мозг.
- **Веб-поиск** через подписку (платная фича; альтернатива — keyless DuckDuckGo).
- Видео не обрабатывает (только кадр-превью).

**🟡 Мелкие шероховатости:** редкие таймауты vision на стикерах / OCR на скринах
(некритично, фолбэк).

## 13. Git: структура и откат

**Два репозитория:**
- `_study/` — инструменты (claude-proxy, шимы, скрипты). Ветка **dev**, основная master.
- `_study/Alice/` — сам рантайм Алисы. Ветки **main** (стабильная) и **dev** (фичи).

**Принцип:** новое делаем на **dev**, `main` — стабильный откат. Теги: `stable`
(рабочая версия), `upstream-original` (китайский оригинал).

**Коммиты на dev (фичи голоса/слуха/имени):**
- `_study`: `e335ec4` (голос+слух), `e3a230a` (start-all.ps1).
- `Alice`: `f64d2e3` (подключение слуха), `ad1d3b5` (узнаёт себя по имени/нику),
  `1a7ab3b` (имя=directed) → `52c9ca5` (revert — оставили имя «мягким»).

**Откат (в обоих репо):**
```powershell
git switch main                      # вернуться на стабильную версию
git reset --hard stable              # жёстко к стабильной точке
git reset --hard upstream-original   # к самому первому (китайскому) оригиналу
```
Когда фича на dev проверена — влить: `git switch main; git merge dev`.

## 15. Нюансы Windows и траблшутинг

- **Node нет в системе** → используется **portable Node 22** в `C:\Users\sozda\node22`
  (в User-PATH). pnpm — через corepack. Если `pnpm`/`node` «не найдены» в новом
  окне — добавь `C:\Users\sozda\node22` в PATH сессии.
- **pnpm 11** читает разрешение нативных сборок из `pnpm-workspace.yaml` →
  `allowBuilds: { better-sqlite3: true, sharp: true, esbuild: true, ... }`.
- **PowerShell 5.1 читает `.ps1` как cp1251** → кириллица в коде скрипта ломает
  парсер. Поэтому все `.ps1` — **только латиницей** (русский живёт в `.py`/`.env`/
  markdown). Кириллицу в аргументах нативных команд PowerShell тоже бьёт — её
  передаём через UTF-8 файлы (например, сообщения git-коммитов через `-F файл`).
- **UTF-8 для Python-консоли:** `PYTHONUTF8=1` (иначе print/лог кириллицы падает с
  `UnicodeEncodeError`). `COQUI_TOS_AGREED=1` — чтобы XTTS не ждал согласия с
  лицензией и не висел.
- **GPU 8 ГБ делят XTTS (~2 ГБ) и Whisper (~2 ГБ)** — влезают вместе благодаря
  оптимизации VRAM. Если памяти не хватит — Whisper можно перевести на CPU
  (`WHISPER_DEVICE=cpu`, медленнее) или взять модель меньше (`medium`).
- **Docker-песочница:** gVisor (`runsc`) на Windows нет → `ALICE_SANDBOX_RUNTIME=`
  пусто (идёт обычный `runc`), образ `alice-skill-runner` собран. Если Docker
  Desktop «сломался» — перезапустить Docker Desktop / WSL.
- **ffmpeg** — лежит в `C:\Users\sozda\ffmpeg\ffmpeg.exe` и в node22 (в PATH);
  нужен Алисе для конвертации голоса MP3/WAV → OGG/Opus.
- **bash-валидация** скиллов: на Windows берётся Git-bash
  (`C:\Program Files\Git\bin\bash.exe`), не WSL-шим.

## 16. Глоссарий

- **Тик (tick)** — один «такт жизни» Алисы: пересчёт давлений → выбор действия →
  исполнение.
- **Давление (P1–P6)** — внутренние силы, толкающие к действию. 0 в простое = норма.
- **Voice (голос личности)** — настрой действия (curiosity/sociability/diligence…),
  не модель.
- **Directed** — сообщение «прямо ко мне» (личка / reply / @-ник) → высший
  приоритет ответа.
- **mentions_alice** — мягкий сигнал «упомянули по имени» (поднимает внимание, но
  не обязывает отвечать).
- **engagement slot** — «окно вовлечения» в конкретный чат на время.
- **switch cost** — задержка при переключении внимания между чатами (имитация
  человека).
- **Dunbar tiers [5,15,50,150,500]** — круги близости; 5 = ближайшие, 500 = дальние.
- **silence / observe_success / message_sent** — исходы тика: смолчала / посмотрела
  и поняла / отправила сообщение.
- **shim (шим)** — маленький локальный сервис-переходник (наш TTS на 5123 и ASR на
  5124, claude-proxy на 8787).
- **membership-guard** — проверка членства в группе перед отправкой (анти-бан).
